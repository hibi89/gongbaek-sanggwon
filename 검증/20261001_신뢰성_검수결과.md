## 10. 납품 샘플·운영 절차·live 차단 재검증

- 현행 taxonomy version과 canonical SHA-256을 기존 납품 PDF/XLSX 샘플 생성기에 넣어 재생성했다. PDF는 2페이지이고 XLSX는 `요약`/`전체 247개` 2개 시트와 247개 상세행을 유지한다. 두 산출물 모두 full SHA-256을 표시하며 PDF 페이지와 XLSX 두 시트를 렌더링해 잘림·겹침이 없는지 확인했다.
- `tests/test_deliverables.py::test_sample_pdf_and_xlsx_embed_current_taxonomy_identity`가 파일 존재, PDF 페이지 수, XLSX 시트/행 수, taxonomy version과 전체 hash를 검증한다. 53개 전체 테스트는 프로젝트와 새 검수 번들에서 각각 통과했다.
- analyzer 연결 거부는 execution 278에서 `Analyze 247 Categories`가 `The service refused the connection`으로 중단된 것으로 확인했다. 운영 analyzer 프로세스는 종료하지 않고 URL을 시험용 미사용 loopback 포트에 잠시 연결했다가 즉시 운영 URL로 복구했다. Analyzer `/health`는 복구 뒤 HTTP 200이었다.
- publication gate 차단은 execution 280에서 Analyzer node에 시험 fixture를 pin해 실제 `Verify Results and Publication Gate`가 `publishable=false`/`publication_gate=blocked`를 거부하는 것으로 확인했다. 리포트 파일 생성 단계는 실행하지 않았다. 검증 뒤 pin을 제거했다.
- 위 실행 후 live n8n workflow DB를 read-only로 확인했다. Analysis Input은 정확히 `주소를 여기에 입력하세요`, Analyzer URL은 운영 loopback URL, `pinData`는 비어 있었다. 실패 실행은 주소를 포함할 수 있어 저장되어 있으며 보관정책에 따라 정리된다. 앞선 주소 검색 재시도 execution 279는 Kakao 주소 결과가 정확히 한 건이 아니어서 좌표 validator에서 막혔고 gate 확인에는 쓰지 않았다.
- 운영 n8n 시작·재시작 절차를 `scripts/start_n8n_with_retention.ps1` 단일 경로로 문서화했다. 이미 실행 중이면 정상 종료 후 wrapper를 실행하고, `-CheckOnly`는 실행 중 프로세스를 변경하지 않는 점검 모드라고 명시했다.
- 주문 분석 절차에는 성공·실패 각각 직후 Analysis Input을 placeholder로 복원하고, 고객 전달 직전에 다시 열어 저장된 값을 확인하는 절차를 추가했다. 검증 당시 placeholder 복구는 workflow DB에서 확인했다.
