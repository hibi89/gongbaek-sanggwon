# 공백상권 크몽 판매전략 최종 검토

검토일: 2026-10-02 · 대상: 현재 프로젝트의 설계, 분석기, n8n V1, 테스트, 운영 절차, 판매 문구, 실제 PDF/XLSX 샘플

이 문서는 이번 검토의 권고안이다. 원래 상품 사양이나 운영 코드를 변경한 문서가 아니다. 기존 문서의 79,000원 가격 동결 지침은 이번 사용자의 가격 재평가 요청에 따라 재검토했다. 아래의 새 지도·확인 카드·보고서 구성은 아직 구현되지 않았다.

## 1. 최종 결정

**공백상권 한 상품을 유지한다. 고객이 받는 내용을 보강한 뒤 단일 가격 59,000원으로 출시한다. 유료 납품에서 품질과 작업시간을 확인한 후 같은 상품을 79,000원으로 올린다. 현재 상태로 79,000원 판매를 시작하는 것은 권하지 않는다.**

브랜드는 **공백상권**, 상품의 역할은 **주소 주변 여러 업종의 공급 공백을 살펴보고 다음 조사 대상을 정리하는 맞춤 보고서**로 정한다.

현재 프로젝트는 원자료 검증과 집계 엔진을 갖춘 자산이다. 다만 납품물은 전체 TOP20과 A TOP10을 표로 보여주는 단계에 가까워, 구매자가 돈을 내고 얻는 실질적인 해석과 다음 행동이 부족하다. 주말 작업의 중심은 엔진 재개발보다 보고서·근거 확인·판매 문구의 재구성이다. 아래 두 가지 출시 차단 문제는 먼저 해결해야 한다.

## 2. 확인한 현재 자산

- 공식 전국 ZIP의 검증 기록은 16개 CSV, 총 2,772,484행, 관측 소분류 247개다. 원본 SHA-256·CRC·스키마·업종 매핑·중복 ID·좌표 검사가 구현돼 있다.
- A/B/C는 사전 운영자 검토를 거쳤으며 현재 A 122개, B 39개, C 86개다. A는 생활·방문형 설명 태그이며 창업 적합도 평가가 아니다.
- 1~5km 누적 집계, 동률의 코드 정렬, 정상 0건과 실패 구분, taxonomy 내용 해시와 발행 게이트가 있다.

- 실제 납품 샘플 PDF 2쪽을 다시 렌더링해 모두 확인했다. XLSX의 `요약`, `전체 247개` 두 시트도 읽고 요약·상세 상단을 다시 렌더링했다. 큰 깨짐이나 겹침은 보이지 않았다. PDF는 표 위주이며, 엑셀 요약은 코드·메타정보의 비중이 높다. Excel 데스크톱에서의 조작은 이번 검토에 포함하지 않았다.

## 3. 가장 큰 상품 문제: 희귀 분류가 좋은 창업 빈틈처럼 보일 수 있다

현재 순서는 5km 점포 수 → 4km → 3km → 2km → 1km → 업종 코드다. 전국적으로 흔한지, 고객의 관심과 맞는지, 실제 대체 경쟁 업종이 있는지는 반영하지 않는다.

현행 샘플의 A TOP10 상위는 다음과 같다.

| A 순위 | 공식 세부업종 | 해당 주소 5km 관측 수 | 전국 해당 분류 관측 수 |
|---:|---|---:|---:|
| 1 | 분류 안된 외국식 음식점 | 0 | 49 |
| 2 | 비디오방 | 2 | 106 |
| 3 | 아이스크림 할인점 | 3 | 237 |
| 4 | 우유 소매업 | 4 | 482 |

전국 값은 현행 taxonomy의 `observed_snapshot_rows`와 검증 보고서의 집계값이다. 해당 서비스를 제공하는 모든 사업체의 실재 총수라는 뜻은 아니다. 예컨대 아이스크림을 판매하는 점포가 다른 소분류로 분류될 수 있으므로 ‘아이스크림 경쟁점이 거의 없다’는 결론은 낼 수 없다.

같은 샘플을 다시 집계한 미관측 업종 수는 다음과 같다.

| 누적 반경 | 전체 247개 중 0개 업종 | A 122개 중 0개 업종 |
|---|---:|---:|
| 1km | 32 | 7 |
| 3km | 3 | 2 |
| 5km | 1 | 1 |

이 주소의 전체 TOP20은 **5km 미관측 1개와 상대적으로 적은 19개**다. ‘공백 업종 20개를 찾아준다’고 쓰면 결과와 맞지 않는다. 현행 판매 문구가 ‘희소 TOP20’이라고 명시한 점은 유지할 가치가 있다.

전체 TOP20에 낚시터, 캠핑/글램핑, 가스 충전소 등도 들어간다. A TOP10도 비디오방·복 요리·전문자격 학원 등을 포함한다. 따라서 A/B/C를 붙이는 것만으로 고객의 다음 조사 후보가 정리되지는 않는다.

**해결은 순위를 임의로 바꾸는 것이 아니라, 같은 결과의 의미를 더 잘 보여주고 고객 관심 업종에 필요한 사실 확인을 추가하는 것이다.**

### 가격 운영

- **현재 그대로의 결과물:** 내 평가로는 39,000~49,000원 수준의 탐색 자료 포지션이다. 현재 상태를 판매하라는 권고가 아니다. 아래 출시 차단은 가격과 무관하게 해결해야 한다.
- **보강한 출시 상품:** 59,000원 한 가격. 지도/범위도, 반경 해설, 관심 업종 최대 3개 확인 카드, 사람이 검수한 PDF/XLSX를 모두 포함한다.
- **다음 가격:** 유료 납품 10건에서 내용 이해 피드백과 작업시간을 확인하고, 수정된 실제 사례를 확보하면 동일 상품의 신규 주문 가격을 79,000원으로 바꾼다. 이미 결제한 주문에는 약속한 가격을 적용한다.
- **인상 기준:** 집계·주소의 중대한 오류가 해결돼 있고, 표준 주문의 실제 직접 작업시간이 90분 이내이며, 고객이 다음 확인 대상을 이해한다는 구체적 피드백이 있어야 한다. 10건은 운영상의 검토 기준이며 가격 효과의 통계 검증을 뜻하지 않는다.
- 초기에는 실제 판매 이력이 없는 ‘정가79,000 → 할인가59,000’ 문구를 쓰지 않는다. 59,000원 자체를 현재 판매가로 표시한다.
- 99,000원 이상은 이번 범위에서 권하지 않는다. 더 높은 가격을 위한 매출·수요 모델을 주말에 급히 추가할 필요도 없다.

| 2 | 분석 중심점·범위 지도 또는 정확한 좌표 기반 범위도, 반경 읽는 법 | 실제 중심과 거리 표시. 1/3/5km는 설명용 강조이며 원래 1~5km 표는 유지 |
| 3 | 생활·방문형 A TOP10과 반경별 공급 해설 | 원래 정렬 유지. 0개와 소수 관측 구분. 전국에서도 드물게 관측되는 분류인지와 해석 한계 설명 |
| 4 | 관심 업종 최대 3개 공백 확인 카드 | 코드·검색일·검색어·출처·관측 사실·추가 확인할 질문 기록 |
| 5 | 전체 희소 TOP20 증빙 | B/C 포함 이유와 동률 표시. 순위가 추천이 아님을 표 가까이 설명 |
| 6 | 방법·자료 한계·현장 확인 체크리스트·출처·버전·검수정보 | 전체 SHA-256 등 기술 정보는 이쪽에 모아 메인 결과의 가독성을 확보 |

6쪽은 설계 목표다. 긴 결과가 있으면 읽기 좋게 나누고, 관심 업종이 1개인 경우 같은 카드를 반복해 페이지를 채우지 않는다. 판매 페이지에서는 기본 내용 범위와 예상 분량을 명시한다.

개발 이관 시 `build_deliverables.py`만 꾸미면 충분하지 않다. `deliver_from_n8n_execution.py`에는 PDF가 정확히 2쪽인지와 시트 이름이 `요약`, `전체 247개`인지 확인하는 고정 조건이 있다. 새 납품 구조에 맞춰 생성기·exporter·테스트·운영 문서의 계약을 함께 갱신한다. 페이지 수만 맞추는 검사 대신 필요한 내용과 수치 일치를 검사한다.

첫 쪽의 숫자는 아래처럼 정의한다.

- ‘1km 공공데이터 미관측 업종 32개’와 ‘생활·방문형 중 7개’를 구분한다.
- ‘실제 가게가 없는 업종 32개’로 바꾸지 않는다.
- 1/3/5km는 가까운 주변/더 넓은 주변을 읽는 설명 구간이다. 도보 생활권·실제 배달권역이라고 부르지 않는다.
- 새 차트의 구간 점포 수는 기존 누적값 차이로 계산한다. 예: 1~3km 구간 = 3km 누적 - 1km 누적. 누적값을 서로 더하지 않는다.

### 확인 카드의 내용과 조사 한계

관심 업종을 주문 시 최대 3개 받는다. 미정이면 음식·소매·생활서비스 등의 관심 분야를 받고, 착수 전에 설명 대상으로 볼 업종 3개를 고객과 확정한다. 자동 희소 순위를 사업 추천 순위로 바꿔 선별하지 않는다. ‘무인 매장’, ‘디저트’처럼 사업 개념과 공식 소분류가 다르면 관련 코드와 포함 한계를 확인한다.

카드마다 다음을 넣는다.

1. 고객의 사업 표현과 연결한 공식 코드·업종명.
2. 1~5km 누적 관측 수와 필요한 구간 분포.
3. 전국 해당 공식 분류 관측 수. 수요나 성공률로 해석하지 않음.
4. 공개지도에서 제한적으로 확인한 표시 사례 또는 미발견 사실. 확인일, 검색어, 검색한 범위, 출처 URL.
5. 해당 상품을 판매하지만 다른 코드에 들어갈 수 있는 대체 업종과 현장 확인 질문.

공개지도 결과는 현재 실제 영업의 전수조사가 아니다. 검색 결과가 없다고 실제 점포 부재를 확정하지 않는다. 공공데이터 0건과 지도상 사례 발견이 다르면 둘 다 기록한다. 원래 집계값을 지도 검색에 맞춰 임의 수정하지 않는다. 수요를 확인하지 못하면 ‘수요 미확인’으로 쓴다.

지도 배경·이미지는 상업적 결과물에 사용할 수 있는 조건과 출처 표시를 확인한 자료를 쓴다. 우선 최소 구현은 분석 중심점과 축척이 정확한 범위도로 만들 수 있다. 실제 도로·건물을 생성형 이미지로 꾸며 지도처럼 제시하지 않는다. 지도 화면을 확인 없이 복제해 판매 이미지에 넣는 방식은 피한다.

**주말의 기본 범위에 가장 가까운 점포 이름·주소 전체 목록까지 추가하지 않는다.** 현재 `stores` DB에는 ID·업종·좌표만 있고 상호·주소가 없다. 점포명 목록을 약속하려면 DB 생성기를 바꾸고 원자료 컬럼을 보존·검증해야 한다(`scripts/build_snapshot_db.py:123`). 공간 분포와 최근 제한적인 지도 확인만으로 먼저 구성한다.

### XLSX: 3개 시트로 충분

- **요약·관심업종:** 고객 관심 카드의 숫자와 해설, 미관측 업종 수, 원래 TOP 목록 링크/안내. 사람이 읽는 요약에 원본 코드·해시를 먼저 나열하지 않는다.
- **전체 247개:** 247행을 유지. 공식명·코드·대/중분류·ABC·1~5km 누적값·기존 순위를 표시. 필터와 헤더 고정, 숫자 단위, 적절한 열 너비. 전국 분류 관측 수는 별도 명확한 열로 추가.
- **기준·출처:** 정의·정렬·동률·자료 기준일·분석일·최근 확인일·전체 해시. 사람이 작성한 확인 메모가 정렬 뒤 다른 업종에 붙지 않도록 업종 코드로 연결.

매출을 입력하는 계산기나 수익 예측 시트를 덧붙이지 않는다. 정적 결과물이 목적이면 실시간 데이터처럼 보이는 재계산 기능을 만들 필요도 없다.

## 6. 출시 전에 해결할 두 가지 차단 문제

### 6-1. 공간 인덱스 검증 누락

독립 기술 감사에서 임시 DB에 현행 247분류와 검증완료 메타데이터, 점포 1개와 공간 인덱스 1개를 넣었다. 정상 분석은 5km 1개였다. 그 뒤 공간 인덱스 행만 삭제하면 5km 0개, `publishable=true`, `publication_gate=passed`로 반환되고 납품 검증도 통과했다. **실제 운영 DB가 손상됐다는 주장과 구분해야 한다.**

원인: `scripts/analyze_gap.py:209` 부근은 `stores` 행 수를 확인하지만 실행 시 RTree와 점포 테이블의 대응을 보장하지 않는다. 구축 시 검사가 있어도 구축 이후 손상은 감지하지 못할 수 있다.

최소 수정: 서비스 시작 또는 스냅샷 승격 시 별도 preflight에서 stores/공간 인덱스의 행 수·ID 대응·좌표 포함 관계·`rtreecheck`를 검사하고, 이상이면 readiness와 발행을 차단한다. 큰 DB 전체 검사를 매 요청마다 할 필요는 없다. 운영 중 DB 파일 교체/변경을 감지하거나 검증한 DB를 보호하는 방법도 정한다. 손상 fixture 테스트를 추가한다.

이번 실제 운영 스냅샷의 읽기 전용 점검에서는 `stores`와 `store_spatial`이 각각 2,772,484행, 고유 ID도 각각 2,772,484개였고 누락·고아 ID가 0개로 일치했다. 따라서 현재 DB의 행/ID 대응 손상 증거는 없었다. `rtreecheck` 재실행은 오래 걸려 중단했으며 이번 완료 검사로 계산하지 않는다. 기존 검증 기록의 통과와 구분한다.

### 6-2. workflow 과거 버전에 주소가 남는 보관 경로

로컬 n8n DB를 읽기 전용으로 조사한 결과, 현재 Analysis Input은 placeholder였지만 V1의 과거 workflow 버전 21개 중 16개에는 비-placeholder 입력 주소가 저장돼 있었다. 주소 문자열은 보고서에 복사하지 않았다. 기존 테스트 주소의 개인정보 여부를 판정한 발견이 아니라, 실제 주문을 같은 방법으로 처리할 경우의 보관 경로 발견이다.

현재 삭제 도구는 특정 execution ID와 주문 파일의 삭제에 초점을 맞춘다. workflow 정의의 과거 버전, 같은 주문의 실패 실행·재실행을 한 주문 단위로 모두 추적하지 않는다. 입력란을 placeholder로 돌리는 것과 execution 한 건을 지우는 것만으로 ‘내부 분석 주소·실행기록 사본은 전달 후 30일 삭제’ 약속을 충분히 이행했다고 볼 수 없다.

최소 수정: 고객 주소를 저장되는 workflow 정의에서 분리해 일회 주문 입력으로 전달한다. 폼/webhook/일회 실행 인자 등 검증 가능한 간단한 방법을 선택하되, 주소를 다른 평문 파일에 장기 보관하는 이동으로 끝내지 않는다. 한 주문에 연결된 성공·실패·재시도 실행 ID와 납품물·임시입력·workflow history·관련 백업의 보관 범위를 정하고, 실제 UI 삭제와 부재 확인까지 리허설한다. 확인 카드에서 생기는 주소 포함 메모도 삭제 범위에 넣는다.

근거: `scripts/expire_deliveries.py:64`, `scripts/expire_deliveries.py:139`, `운영/주문_분석_납품_실행절차.md:23`, `운영/주문_분석_납품_실행절차.md:49`, 로컬 n8n read-only 구조 조사. 운영 n8n DB의 주소나 credential을 GitHub/웹 검토 묶음에 넣지 않는다. 구조 변경·정리는 복구 방법을 확보한 후 수행한다.

**한 곳에서만 바꿀 기준:** 가격·포함 범위·수정·납기·보관 조건은 `docs/product.md`를 기준으로 다른 판매/운영 문서에 반영한다. 데이터 기준일·스냅샷 ID·DB 경로는 데이터 설정으로 단일화한다. 현재의 20260630 하드코딩은 다음 분기 갱신 시 누락될 수 있다. 분류 수가 바뀌면 247이라는 상품 약속도 검토하고, 새 자료가 자동으로 기존 사양과 같다고 가정하지 않는다.

GitHub는 작업용 비공개 저장소로 시작하는 것을 권한다. 상용 엔진을 공개할지는 별도 결정이다. 비공개라도 고객 자료·키는 넣지 않는다. `.gitignore`는 이미 커밋된 자료를 제거하지 못하므로 최초 업로드 전에 파일 목록을 검토한다.

올릴 것: 현행 코드·테스트·버전/의존성 파일·정리된 문서·작은 합성 fixture·정확히 비식별한 샘플·credential 값이 없는 workflow.

제외할 것: `.env`, 토큰/API 키, 운영 n8n DB/과거 버전/실행 export, 고객 주소/확인 메모/결과, 삭제 대장, 원자료 ZIP/CSV, 대형 SQLite, `__pycache__`, `.venv`, 임시 미리보기, 로컬 경로·credential 정보를 포함한 로그. 현재 원자료 ZIP만 약 353MB이므로 웹 검토나 일반 코드 업로드 묶음에 통째로 넣을 이유가 없다.

웹 대화에 전달할 첫 묶음은 **이 최종 검토 문서 + 주말 수정 지시서 + 현행 비식별 PDF/XLSX + 판매 문구**면 충분하다. 코드 단계에서 scripts/tests/workflow/taxonomy와 fixture를 추가한다. 웹 대화가 운영 DB를 보지 못하면 전체 원본 행 정확성이나 현 서비스 상태를 직접 확인했다고 쓰지 않게 한다.

## 9. 주말 실행 순서와 완료 기준

권장 작업일은 2026-10-03~04다. 이 기간에 모든 자동화까지 완성된다고 보장하지 않는다. 핵심 내용과 안전한 주문 흐름을 우선 마감한다.

## 10. 검토 범위와 미확인

현재 파일과 원자료/검증 기록을 읽고 샘플·코드·테스트를 검토했다. 전국 모든 원자료 행을 이번에 다시 적재하거나 현실 점포와 전수 대조하지 않았다. 현재 현장 영업 상태, 실제 유료 구매 전환, 크몽 계정/카테고리별 적용 수수료, 개별 지도 서비스의 결과물 이용조건은 미확인이다. 기존 n8n live E2E는 기록을 검토했으며 이번에 고객 주소로 새 실행을 만들지 않았다.

가격·페이지 구성·공수 목표는 시장 표본과 현재 산출물에 근거한 전략 판단이다. 거래 성과를 보장하는 수치가 아니다. 주말 후 다음 담당자는 이 문서를 기준으로 구현 여부를 확인하며, 권고 항목을 이미 완료된 기능으로 소개하지 않아야 한다.
