# 구현 현황 및 출시 준비 상태

기준일: 2026-09-30 · 상품: **공공데이터 기반 247개 업종 공백상권 분석 / 79,000원**

## 현재 판정

2026-10-01 기준 핵심 데이터 처리, 정상 주소 E2E, 요청된 analyzer 연결 거부와 publication gate 차단의 live n8n 경로를 확인했다. 247개 taxonomy 해시가 들어간 PDF/XLSX 샘플을 다시 만들고 파일 자체를 확인하는 자동 테스트를 추가해 전체 53개 테스트가 통과했다. 납품물은 PDF 요약+XLSX 상세, 표준 납기는 영업일 2일, 주소 수정은 분석 전, 보관은 전달 후 30일이다. 납품 파일 생성은 현재 n8n 다음에 운영자가 실행하는 CLI 단계이며 n8n 자동 노드는 아니다. n8n 시작 절차는 보관 설정이 적용되는 전용 스크립트로 고정했다. 실제 크몽 주문 운영과 실제 만료 시 n8n UI 실행기록 삭제는 아직 수행하지 않아 **크몽 공개 등록 전** 상태다.

## 판매 공개 전에 남은 일

1. 입력 누락·Kakao 인증·analyzer credential·좌표검증 실패와 Analyzer 연결 거부·publication gate 거부는 모두 live n8n 오류 중단을 확인했다. [실패 기록](../검증/20260930_n8n_실패경로_기록.md).
2. 기본 `%LOCALAPPDATA%` 실파일 생성은 실행 272로 검증했다. 첫 실제 주문에서는 주소·기준일·순위 수치의 수동 검수와 고객 전달을 리허설한다.
3. 결과 전달 후 30일 삭제는 운영자가 실행하는 절차다. 주문별 정리 CLI와 격리 DB/폴더 기반 안전 테스트, 가짜 주문 end-to-end 리허설을 완료했다. 실제 n8n UI execution 삭제 및 고객 주문 정리 리허설은 남았다. n8n 보관 시작 설정은 전용 스크립트로 설정하되, 이미 실행 중인 프로세스의 환경변수를 직접 읽어 확인한 것은 아니다.
4. 환불·분석 시작 후 주소 수정 기준을 크몽 주문 조건과 맞추고, 접수부터 분석·수동 검수·고객 전달·삭제대장 기록까지 한 건을 리허설한다.
5. 판매 운영 시 분석기를 어떤 PC에서 어떻게 켜둘지 확정하고, 로컬 n8n이 꺼져 있을 때 주문이 접수되지 않도록 운영 절차를 둔다.

## V1 범위와 표현

- 점포 수는 검증된 전국 CSV 스냅샷에서 계산한다. Kakao Local은 주소를 좌표로 바꾸는 데만 쓴다.
- 주문마다 소상공인 API를 호출하거나 매출·유동인구·배달 주문량을 추정하지 않는다.
- ‘공백·희소’는 데이터 기준일에 해당 거리 내에서 관측된 점포 수다. 수요·수익성·창업 성공을 뜻하지 않는다.
- 조회·매핑·스냅샷 오류를 0개로 바꾸지 않는다. 품질 gate를 통과하지 못하면 리포트를 전달하지 않는다.
