| RET-01 30일 도래일 | 전달일+30일인 날짜와 하루 전/하루 뒤를 각각 평가한다. | 도래일 이전은 삭제하지 않고, 도래일 당일에는 dry-run 삭제 후보로 표시한다. |

| RET-03 안전 삭제 | 만료된 주문 폴더를 준비하고 n8n execution row를 제거한 격리 DB를 사용한다. | `--apply`에서 주문 폴더가 사라지고 삭제 확인일 및 `삭제완료`가 대장에 기록된다. |
| RET-04 fail-closed | n8n DB 누락, 만료일 계산 오류, 중복 execution ID, 경로 탈출 ID, 알 수 없는 상태를 각각 입력한다. | 오류 또는 `manual_review_unknown_status`로 멈추며 주문 파일을 삭제하지 않는다. |

## 3. 수집 방식별 최소 완료 기록

실제 n8n execution을 UI에서 삭제하는 단계는 이 자동 테스트로 대체되지 않는다. RET-02/03은 격리 SQLite와 임시 파일의 삭제 동작만 확인한다.

### 전국 파일 snapshot

- 공식 원자료 출처와 기준일 기록.
- 파일 다운로드 성공, 파일 크기·checksum 등 무결성 확인.
- 파싱 행 수와 적재 행 수 일치 여부.
- 좌표·업종코드 정규화와 전체 taxonomy 매핑 상태.
- 중복 처리 수, 미지원·미분류 코드와 이유.
- snapshot을 `complete`로 승격한 근거.

### 반경 API

- 요청 업종 코드와 각 응답 결과 코드 기록.
- 업종별 totalCount, 예정·성공·실패 페이지 수, 수신 행 수.
- 재시도 및 중복 페이지 처리 내역.
- 성공적인 명시적 빈 응답과 오류 응답을 구분한 로그.

## 4. 출시 승인 기준

- 모든 필수 시나리오를 실행하고 기대 결과를 확인한다.
- 실패 케이스에서 완성 리포트가 발행되지 않는 것을 확인한다.
- 코드 교차표 및 A/B/C 태그표의 실제 버전을 실행 기록에 남긴다.
- 테스트 주소와 고객에게 전달할 자료가 같은 기준일·분류표·분석엔진 버전을 가리킨다.
- 미해결 실패가 있으면 판매 개시를 보류하고 수정 후 해당 시나리오를 다시 실행한다.
