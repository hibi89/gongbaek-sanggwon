# 크몽 주문 분석·납품 실행 절차

상품: 공공데이터 기반 247개 업종 공백상권 분석 · 79,000원  
납품: PDF 요약 + XLSX 상세 · 표준 납기 영업일 2일  
주소 변경: 분석 착수 전 허용 · 보관: 결과 전달 후 30일

## n8n 시작·재시작 — 전용 스크립트만 사용

운영 n8n은 프로젝트 루트에서 `./scripts/start_n8n_with_retention.ps1`로만 시작·재시작한다. 스크립트가 고정 버전을 확인하고 실행기록 보관 설정을 적용한다. `n8n start`나 `n8n.cmd start` 직접 실행은 사용하지 않는다. 포트 5678이 이미 열려 있으면 기존 n8n을 정상 종료한 뒤 스크립트를 실행한다. `-CheckOnly`는 점검 전용이며 시작 또는 실행 중인 프로세스 변경을 하지 않는다.

## 주문 접수 전

1. 고객에게 분석 주소, 자료 갱신 기준일, 공백·희소는 공급 점포 관측값이며 수요나 수익성 보장이 아니라는 점을 안내한다.
2. 접수된 주소를 주문 메시지와 대조한다. 분석을 시작하기 전까지 주소 변경을 반영한다.
3. `http://127.0.0.1:5678/healthz`의 `status=ok`와 `http://127.0.0.1:8765/health`의 `status=ready`, 업종 수 247을 확인한다. Analyzer의 taxonomy hash와 version이 `설계/03_업종분류표.json`의 값과 정확히 일치해야 한다.

## 분석 실행

1. n8n의 **공백상권 분석 V1 - 247개 업종** workflow를 열고 Analysis Input에 확정 주소를 입력한다.
2. Manual Trigger부터 전체 실행한다. 완료 뒤 execution ID를 기록한다.
3. Kakao 응답 200과 주소 결과 1건, 정상 좌표, analyzer 응답 200, 전체 카테고리 247, 미분류 0, 전체 TOP20 20, A TOP10 10, `publication_gate=passed`를 확인한다.
4. 실행이 실패하거나 조건이 하나라도 맞지 않으면 납품물을 만들지 않는다. 주소와 실패 노드를 확인하고 성공한 새 실행을 만든다.
5. 실행이 끝나면 성공·실패와 관계없이 즉시 Analysis Input을 `주소를 여기에 입력하세요`로 복원하고 저장한다. 노드를 다시 열어 placeholder가 저장된 것을 확인한다. n8n 실행기록은 별도로 남을 수 있으므로 입력란 복원은 기록 만료를 대신하지 않는다.

## PDF·XLSX 만들기와 확인

프로젝트 폴더에서 먼저 read-only 확인을 실행한다.

```powershell
$python = '.\.venv\Scripts\python.exe'
& $python scripts\deliver_from_n8n_execution.py --execution-id <실행ID> --check-only
```

결과가 `validated`이고 publication gate가 `passed`일 때 파일을 생성한다.

```powershell
& $python scripts\deliver_from_n8n_execution.py --execution-id <실행ID>
```

파일은 기본적으로 `%LOCALAPPDATA%\GapAnalysis\deliveries\<request_id>`에 저장된다. 파일 생성 응답과 `manifest.json`에서 파일명·바이트 수·SHA-256을 확인한다. PDF 2페이지, 주소·기준일·분류표 버전, XLSX `요약` 및 `전체 247개` 시트, 상세 247행, TOP20/A TOP10 수치가 일치하는지 사람이 열어 마지막으로 검토한다. 파일이 없거나 크기가 0이거나 검토를 통과하지 못하면 전달하지 않는다.

현재 PDF/XLSX 생성은 n8n workflow 노드가 아니라 이 로컬 CLI 단계다. 프로젝트 폴더의 `output/samples/gap-271/`은 비식별 샘플이며 실제 주문 납품물로 보내지 않는다.

고객에게 전달하기 직전에 workflow의 Analysis Input을 다시 열어 값이 정확히 `주소를 여기에 입력하세요`인지 확인한다. 다른 값이면 고객 전달을 보류하고 placeholder 복원·저장을 마친 뒤 다시 확인한다.

## 고객 전달과 삭제 기록

1. 검토한 PDF와 XLSX를 해당 크몽 주문에 수동 전달한다. 분석 실패나 미완료 상태에서 성공으로 안내하지 않는다.
2. 전달일에 `운영/30일_보관_삭제_대장.csv`에 분석번호, n8n 실행 ID, 전달일, 전달일+30일 삭제 예정일을 기록하고 처리상태를 `보관중`으로 적는다. 주소와 고객 연락처는 적지 않는다.
3. 삭제 예정일에 대장과 n8n 실행 목록을 확인한다. 해당 실행기록이 있으면 n8n UI에서 그 기록을 삭제한다. 그 후 아래 명령으로 먼저 dry-run한다.

   ```powershell
   & $python scripts\expire_deliveries.py
   ```

   실행기록이 남아 있으면 `delete_n8n_execution_first`가 표시되고 파일 삭제는 보류된다. `would_delete_files`만 확인되면 아래 명령으로 LocalAppData의 주문 폴더(PDF·XLSX·manifest)를 삭제하고 대장을 갱신한다.

   ```powershell
   & $python scripts\expire_deliveries.py --apply
   ```

4. n8n UI에서 실행기록이 사라진 것, 주문 폴더가 사라진 것, 대장 상태가 `삭제완료`이며 삭제 확인일이 기록된 것을 각각 확인한다. 별도 임시 파일이 있으면 운영자가 수동 삭제 후 부재를 확인한다.

현재 n8n은 `scripts/start_n8n_with_retention.ps1`로 재기동했다. 시작 로그에 pruning 900시간(37.5일), count 제한 없음이 기록됐고 재기동 후 health와 전체 실행 272가 성공했다. 프로세스 내부 환경변수 직접 read-back은 OS 권한상 미확인이다. 900시간은 실행 시작 기준 자동 정리이며 전달일로부터 정확히 30일인 고객 파일 삭제를 대신하지 않는다. 고객 파일은 아래 삭제대장 기준으로 전달일+30일에 운영자가 제거하고, n8n 실행기록과 파일이 실제로 없어졌는지 각각 확인한다.

## 검증 기준과 제한

- 정상 전체 E2E는 execution 271·272와 공개 주소 273~277에서 확인했다. 입력 누락, Kakao 인증 실패, Analyzer credential 형식 오류, 좌표검증 실패와 Analyzer 연결 거부(execution 278), publication gate 차단(execution 280)도 live n8n 오류 중단을 확인했다. 세부 기록은 [실패 경로 확인](../검증/20260930_n8n_실패경로_기록.md).
- `%LOCALAPPDATA%` 기본 경로의 실파일 생성은 execution 272 테스트로 검증했다. 첫 고객 주문에서는 생성된 PDF/XLSX 내용과 주소를 마지막으로 직접 검수한다.
- 이 PC가 꺼져 있거나 n8n/analyzer가 중단되면 로컬 분석을 실행할 수 없다. 실제 주문 전에 두 서비스 health를 확인한다.
- 분석 자료는 2026-06-30 기준 전국 상가 snapshot이며 실시간 점포 확인이나 창업 수익 예측이 아니다.
